# Constitution — Maletín de experiencias

## Principios fundamentales

1. **Fidelidad pedagógica:** mantener los bloques, conceptos y contenidos curriculares presentes en el documento fuente. No inventar referencias curriculares ni atribuir fuentes no provistas.
2. **Coherencia de redacción:** usar la primera experiencia de Primer Año como patrón de tono, estructura y nivel de detalle: objetivo concreto, materiales enumerados y desarrollo secuenciado en instrucciones claras dirigidas a la implementación docente.
3. **Accesibilidad primero:** la web debe usar contraste WCAG AA como mínimo, texto base amplio (objetivo 18–20 px), jerarquías claras, foco visible, navegación por teclado, controles amplios y respetar prefers-reduced-motion.
4. **Diseño escolar consistente:** identidad visual de útiles escolares e ilustraciones lineales coloridas, paleta pastel equilibrada y superficies claras. Los adornos nunca deben competir con el texto.
5. **Una fuente de contenido:** las 24 experiencias deben conservar una única fuente de datos que alimente la web y facilite la generación del PDF, evitando divergencias.
6. **Navegación significativa:** índice y navegación de la web deben conducir a secciones reales mediante anclas/enlaces accesibles.
7. **Descarga confiable:** el botón del header debe descargar/abrir el PDF final versionado del proyecto, nunca un archivo placeholder.
8. **Calidad verificable:** validar enlaces internos, contenido completo, responsive, accesibilidad, render del PDF y funcionamiento de descarga antes de considerar terminada una etapa.

## Restricciones
- No alterar el sentido de los contenidos curriculares de las fichas.
- No eliminar el espacio para registro/imágenes de experiencias.
- No usar fondos estampados de alta densidad detrás de párrafos largos.
- Las animaciones serán breves, funcionales y no bloquearán la lectura.
- No publicar un PDF o contenido de muestra como si fuera la entrega definitiva.

## Flujo de trabajo
Spec-Driven Development: Constitution → Specify → Clarify → Plan → Tasks → Analyze → Implement → verificación/convergencia. Cada fase debe dejar artefactos revisables y trazables.
